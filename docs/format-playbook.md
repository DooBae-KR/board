# 숏폼 카테고리별 흐름 (플레이북)

기존 "레포 한 개 소개" 대본이 늘어졌다는 판단으로, 참고 영상 3개의 **형식**을 카테고리로 나누고 카테고리마다 흐름·컷 길이·화면을 정한다. 이 문서가 새 기준이다(기존 5장면 규격 `docs/video-spec.md`는 레포 소개 변형으로만 남긴다).

> 참고 영상 3개는 제목·채널만 확인했고 화면과 대사는 보지 못했다. 아래 흐름은 제목과 요청(직관적으로 볼 수 있는, 예시와 함께 쉽게 설명하는 애니메이션, 뉴스)에서 도출한 설계안이다. 실제 영상과 다르면 이 문서를 고친다.
> - A: Solostack, 「GitHub 트렌딩 Top 10 (9월 1주) — 1위는 또 다이어그램 스킬」
> - B: Boltlee 개발노트, 「로드밸런서가 한 서버에만 트래픽을 몰아주는 이유」
> - C: Solostack, 「코딩 에이전트로 게임 두 개를 합쳤어요, OpenAI 수학 논문은 3편 철회 | 이번 주 AI 뉴스 TOP5」

## 공통 원칙 (루즈함 방지)
| 항목 | 기준 |
|---|---|
| 첫 1.5초 | 훅. 결과·숫자·의문 중 하나를 화면 문구와 첫 문장에 동시에 |
| 컷 길이 | 한 컷 2~4초. 6초를 넘는 컷 금지. 컷마다 화면이 바뀌거나 새 요소가 나온다 |
| 정보 밀도 | 컷당 정보 하나. 문장 하나 = 컷 하나 |
| 문장 | 12~22음절 구어체 존댓말. 접속·군더더기("그래서", "자 이제") 삭제 |
| 속도 | 최종 길이(1.2배속 적용 후) 기준. 음성은 초당 약 5음절 이하 |
| 전환 | 페이드 0.12초 이하, 요소 등장 0.25초 이하 |
| 사실 | 직접 확인한 것만. 숫자는 기준일, 뉴스는 출처·날짜. 확인 못 하면 '미확인'으로 빼기 |
| 베끼기 금지 | 참고 영상의 문장·항목 선정·순서를 복제하지 않는다. 형식만 참고하고 내용은 직접 조사 |
| 마무리 | 행동 하나. 팔로우 후 댓글 키워드 → DM |

## A. 주간 트렌딩 TOP N (순위 카드, 직관적으로 한눈에)
최종 길이 35~40초, TOP 5(필요하면 TOP 3).
| 구간 | 컷 | 화면 | 나레이션 예산 |
|---|---|---|---|
| 0~2초 | 훅 | "이번 주 GitHub 트렌딩 TOP5" + 1위 예고(이름 가리기 또는 한 줄) | 14음절 이하 |
| 2~5초 | 기준 | 기준 한 줄(어디의 어느 기간 기준인지, 기준일) | 16음절 이하 |
| 5~25초 | 5위→1위 카운트다운 | 순위 카드 5장, 각 4초: 순위 숫자, 레포 이름, 한 줄 역할, ★ 수 칩, 라이선스 칩 | 카드당 18음절 이하 |
| 25~32초 | 1위 확대 | 1위 카드를 키우고 "왜 뜨나" 한 줄과 쓰는 모습 한 컷 | 30음절 이하 |
| 32~37초 | 한 줄 요약 | "오늘의 한 줄" 한계 문구(별 수가 품질 보장은 아님) 포함 | 22음절 이하 |
| 37~40초 | CTA | 키워드 배지(예: `트렌딩`) → DM으로 전체 목록 링크 | 22음절 이하 |
- 데이터: GitHub 트렌딩(주간) 페이지에서 직접 읽은 순위·★·언어·라이선스. 못 읽으면 만들지 않는다.
- 레포 설명은 README 첫 줄에서 확인한 사실만.

## B. 개념 해설 애니메이션 (예시와 함께 쉽게)
최종 길이 32~38초. IT·Claude·개발 개념 하나를 "왜 ~일까?" 질문 하나로.
| 구간 | 컷 | 화면 | 나레이션 예산 |
|---|---|---|---|
| 0~2.5초 | 의문 훅 | 질문 문구 + 일상 비유 그림 하나 | 18음절 이하 |
| 2.5~8초 | 기대하는 모습 | 기대하는 동작 애니메이션(박스·화살표) | 28음절 이하 |
| 8~15초 | 실제로는 | 문제 상황 애니메이션(빨강 ✗) | 32음절 이하 |
| 15~24초 | 원인 한 가지 | 핵심 규칙 하나를 단계별 도식으로(칸 3개, 하이라이트 이동) | 45음절 이하 |
| 24~31초 | 예시 | 숫자·값 한두 개를 넣은 구체 예시 한 컷(초록 ✓) | 35음절 이하 |
| 31~35초 | 한 줄 정리 + 레포 한 개 | 개념 요약 한 줄 + 관련 오픈소스 레포 이름·★·라이선스 한 줄 | 28음절 이하 |
| 35~38초 | CTA | 키워드 → DM으로 레포 링크 | 22음절 이하 |
- 개념 설명은 일반적으로 확립된 사실(공식 문서·표준)만. 추측으로 동작을 그리지 않는다.
- 도식은 `why.diagram`처럼 "문제 줄 → 해결 줄" 구조를 확장해 쓴다(생성기 지원 예정).

## C. 주간 AI·IT 뉴스 TOP5
최종 길이 36~40초.
| 구간 | 컷 | 화면 | 나레이션 예산 |
|---|---|---|---|
| 0~3초 | 훅 | "이번 주 AI 뉴스 TOP5" + 가장 큰 두 건의 헤드라인 | 24음절 이하 |
| 3~33초 | 뉴스 5건 | 건당 6초: 번호, 헤드라인(한 줄), 한 줄 요약, 출처·날짜 칩 | 건당 28음절 이하 |
| 33~37초 | 한 줄 정리 | 이번 주를 묶는 사실 한 줄(의견·예측 금지) | 22음절 이하 |
| 37~40초 | CTA | 키워드 → DM으로 출처 링크 모음 | 22음절 이하 |
- 뉴스는 1차 출처(발표 원문, 공식 블로그, 논문 페이지)를 직접 열어 확인한다. 언론 기사만 있으면 기사 출처를 적고 '보도' 표현을 쓴다.
- 날짜가 지난 소식, 루머, 확인 안 된 수치는 넣지 않는다. 이번 주 기준 최근 7일.
- 다른 채널의 뉴스 선정·문장을 따라 쓰지 않는다.

## 산출물 위치
- 카테고리별 대본: `docs/scripts/<카테고리>-<YYYY-MM-DD>.md`(A=`trending`, B=`concept`, C=`news`). 장면표에 컷별 시간·화면·나레이션·음절 수·출처를 적는다.
- 영상 스토리 JSON과 생성기 템플릿은 카테고리별 대본이 확정된 뒤 만든다.
